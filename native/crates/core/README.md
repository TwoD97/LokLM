# loklm-core 0.1

Shared Rust logic ported from LokLM revision `4651557`. Use
`loklm-core = { path = "…/native/crates/core", default-features = false }`
for pure chunking/model preprocessing/ranking/session/crypto APIs. The optional
`storage` feature includes encrypted SQLite and desktop vault compatibility.
This crate manifest does not inherit workspace fields and can be consumed in
the headless worktree independently.

`chunking::{chunk_markdown, chunk_pages}` preserves heading/page provenance,
recursive 2000-character splitting, 200-character overlap where it fits, fenced
code and repeated table headers. `CHUNKER_VERSION` marks Unicode scalar budgets
instead of JS UTF-16 budgets. It does not claim exact original-file byte offsets.

`models::{sanitize_passage,prepare_query,normalize,fingerprint}` preserves the
existing raw passage/BGE-M3 no-instruction/Qwen instruction behavior. Fingerprints
require an actual SHA256 and include model/dimension/preprocessing policy. They
do not infer compatibility from model stems. No model is downloaded or loaded.

`retrieval::fuse_rrf` matches current stable RRF-list fusion (k=60), deduplicates
within each arm and caps only after all contributions are summed. It does not
replace evidence checks/reranking or pretend lexical search is dense retrieval.

Fixtures under `tests/fixtures` are synthetic outputs of the actual original
TypeScript implementation, generated by `native/scripts/original-fixtures.ts`.
The explicitly synthetic credentials are public test constants, never real keys.
`recovery-words.txt` is the existing BIP-39 English public-domain wordlist from
`src/shared/passPhraseWords/wordlist-en.ts`; schema.sql is the current app schema.

Storage feature work is in progress. No real-vault migration is authorized by
these APIs and no production data is opened by tests.

# PDF text-layer preview

`native/crates/documents` uses pinned Rust `pdf-extract 0.12.1` / `lopdf 0.42.0`.
The desktop sends up to 16 MiB of source bytes to a separate copy of its executable
through private pipes. No source path, vault key, application environment, temp
plaintext file or network listener is involved. The worker environment contains
only Windows SystemRoot. Stderr is discarded and errors expose fixed messages.

Before supplying document bytes, the parent assigns the worker to a Windows Job
Object: 512 MiB committed process memory, one process and kill-on-job-close. A
30-second parent deadline and session cancellation kill and reap that worker.
This is process/resource isolation, **not a security sandbox**: the worker still
runs as the current Windows user. Other operating systems currently refuse this
path until equivalent resource limits and tests exist. See Microsoft's
[job documentation](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
and [memory-limit definition](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information).

The parser walks every page explicitly using
[`output_doc_page`](https://docs.rs/pdf-extract/0.12.1/pdf_extract/fn.output_doc_page.html).
It does not use the convenience per-page iterator, whose error handling can
return a prefix of a document. Output is bounded to 16 MiB and 1,000 pages.
Original-byte SHA-256 identifies the source independently of extracted text.
Only a complete successful parse enters one encrypted database transaction.
Duplicate sources are retained once; changed-source replacement remains refused
so previous chunks, vectors and citations survive.

This slice deliberately rejects images, form XObjects, attachments, annotations,
AcroForms, bookmark hierarchies, encrypted documents and pages without extracted
text. They require OCR/full PDF handling or explicit blank-page review; none is
silently omitted. This is limited text-layer support, not PDF/OCR parity, PDF
visual rendering, layout equivalence or a guarantee about every font encoding.
Indexed source opening displays extracted text and original page number.

Fixtures are generated by `node native/scripts/pdf-fixtures.mjs --write` and
contain only synthetic German/English text. Rust tests check Unicode/page
identity, malformed later pages, expansion limits and required OCR rejection.
`cargo run -p loklm-documents --example isolated --manifest-path native/Cargo.toml`
exercises actual private pipes and the Job Object on Windows without loading a
model. `LOKLM_TEST_PDF=1 node native/scripts/native-ui.mjs` runs the PDF variant of
the actual Windows UI workflow, including failed import retention and page opening.

## Manual testing

1. Build the normal native preview as described in MANUAL_TESTING.md; create a new
   synthetic vault and workspace. Do not select a real vault.
2. Import `native/crates/documents/tests/fixtures/synthetic.pdf`. Search for
   `Berlin`, open the hit, and expect German text and page 1. Search `ALPHA`, open
   that hit, and expect page 2 and the original literal script-like text.
3. Import the same file again; expect one document and unchanged source IDs.
4. Import each `broken-page.pdf`, `blank-page.pdf` and `image.pdf` fixture; expect
   a visible error, no added document, and the earlier sources still available.
5. Lock during a larger synthetic PDF import. Expect no late UI/source content or
   surviving worker; reopen the vault and inspect whether the operation completed
   before revocation or was cancelled. Never accept a partially indexed document.

`node native/scripts/pdf-stress.mjs` generates one synthetic 512 MiB compressed
expansion stream without allocating that input in the parent. The Windows worker
rejected it, and separate runs confirmed concurrent cancellation and session lock
stop and reap workers. This is one stress case, not comprehensive PDF fuzzing.
The original TypeScript parser agrees on whitespace-normalized text and page
numbers for the two-page fixture (`pdf-original-compat.ts`); broad parser/layout
equivalence remains a release gate.

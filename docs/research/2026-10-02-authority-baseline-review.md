# Authority baseline: independent source review

These observations use the unchanged production build at the start of October 2. They are development evidence, not a new held-out result. Every judgment below compares the generated claims with the original imported chunks and the supplied citation events. A supplied document, a correct number, or an exact quote alone is not proof that the answer's inference or authority claim is supported.

Thus five of the first six completed DEV requests have fully supported, complete answers in this review; the other has the right policy decision with a citation/explanation defect. The seventh has useful correct partial reasoning but fails the completion requirement. These tiny, deliberately diagnostic cases do not estimate real-world accuracy. The production model can both resolve approved authority correctly and invent authority despite explicit contrary text, so blanket refusal and unconditional trust in source-order are both inappropriate fixes.

The original baseline collectors predate the new authoritative-invoke/terminal reconciliation. Their raw token streams, done events, cancellation outcome, and observed elapsed times remain intact. Later runs record invoke settlement, terminal origin/mismatch, and the configured timeout explicitly. Do not silently pool those transport definitions or compare a timed-out partial against a complete answer as if latency and quality were equivalent.

The separate `authority-20261002-baseline-dev08` follow-up completed case 08 in 118.52 s. It correctly translates both German sources, gives `/v6/export` and UTF-8 JSON, and attributes the manual and deployment observations to their own source IDs. The new collector records a completed terminal, settled invoke, and no mismatch. This makes six fully supported completed answers across the eight DEV cases when the separate follow-up is included; one remains partially cited and one timed out. It does not retroactively make the first eight-case run complete, or provide a uniform warm/cold timing sample.

Manual judgments are stored alongside each run in `manual.json`; `review.json` adds mechanical source/terminal diagnostics. Mechanical checks remain distinct from these semantic judgments. The reserved corpus remains unopened by the implementation/tuning agents.

## First assessment prototype: separate development experiment

`out/optimization-20261002/evidence-order-candidate-a` was stopped after three completed fixed-context calls and five unobserved plans. DEV01 in A-B, B-A and A-B-Acopy order produced the appropriate visible `unresolved` label, but **0/3 outputs were valid JSON and 0/3 contained complete conflict evidence**. Each omitted the outer opening brace and quoted only source prefixes, leaving out both admission totals and final-approval status. The answerable proposal/control case was not reached, so this run says nothing about false refusal on it.

Observed assessment times were 85.93, 81.68 and 116.30 seconds after a 40.05-second load, at 8192 tokens and 14/33 GPU layers. These are costs of the extra assessment alone, not final-answer latency. The raw observations remain unchanged, with a separate stop record and parser/manual reviews. A later transport repair or different assessment representation must be identified as a new candidate and measured again; it cannot retroactively turn these failures into passes.

Candidate B tested two explicitly selected A-B controls after the response-boundary fix; six other variants were unrequested. Both outputs parsed. DEV01 selected the correct conflicting totals and unresolved relation in 41.47 s, though its spans omitted approval qualifiers. DEV03 selected true evidence in 63.23 s but assigned authority backwards: the unapproved proposal's explicit denial of approval supposedly overrides the still-active certificate. Structural and literal-span checks accepted that invalid resolution. This validates the narrow syntax repair on two controls and exposes a separate semantic limit; it does not establish final-answer quality, which the probe does not exercise.

V2's numbered-unit variant then completed two selected controls in 28.54 and 34.31 seconds. Both relation labels were appropriate, but both failed its unchanged parser's contiguity rule. The active-certificate selection additionally omitted the actual authorized capacity, even with the original neighboring-unit expansion. These outputs remain failures under V2; later reconstruction rules cannot retroactively pass them.

## Prompt-only B application result

The actual application run `authority-20261002-prompt-b-conflict` completed all four original cases with assessment disabled. Every answer preserved the correct authority/finality decision; strict full compliance was 2/4, with 2/4 partial. The German unresolved answer avoided the earlier invented supersession but omitted both competing dates. The English approved-revision answer repaired its earlier attribution error and cited both sources correctly. The German approved-revision answer supported every emitted claim from revision2 but used a natural-language date instead of the requested ISO form.

Its four-request median total was 67.12 seconds, with no timeout or terminal mismatch. The configured timeout was 300 seconds rather than the original 180 seconds, although every answer completed below both cutoffs. “Prompt-only” denotes assessment disabled; multiple changes were bundled in B, so this is not an isolated causal test of prompt wording. B's executed compiled output stayed unchanged while subsequent source-only work continued. The raw working-tree source hashes must not be equated with a build-time source mapping.

# Local RAG reliability work — 2 October 2026

The production changes correct native output handling, strengthen claim-level citation and authority instructions, align answer depth with the context actually loaded, and reject incomplete provider streams. The optional second-pass evidence assessment remains **off by default**: the real application test produced a false refusal, irrelevant quotations and substantial extra latency. It is a developer diagnostic, not an adopted quality improvement.

This report records compiled candidate E. Its two selected DEV controls passed, but the reused Orvo conflict still exposes a critical limitation: the model invents supersession and declares an unapproved draft definitive. A separate correct inspection count cites the wrong passage. The fresh reserved test also fails on overlapping counts, seasonal scope, equivalent units and code evaluation, with an additional attribution error. ## Product changes

- **Native Qwen output:** the public closed-thought Qwen3.5 wrapper avoids losing the first generated token inside an automatically opened thought segment. This was observed as missing opening JSON braces. Raw utility output preserves literal text such as `<think>` inside JSON rather than treating every matching string as hidden reasoning. Responses are not repaired by inventing missing characters.
- **Grounded answers:** English and German prompts require all supporting passages for a claim combining sources. They distinguish genuine disagreement from different scope, date or equivalent units, and require explicit authority for supersession. Recency, repeated passages and missing approval cannot establish a winner. These instructions improve the contract; they do not prove every generated claim follows it.
- **Actual capacity and budgets:** hardware-limited FULL at 8192 tokens uses the same standard document-answer depth as the 4B LITE profile. Prompt synchronization follows load/restore and direct requests. Native budget checks measure complete framed prompts with the tokenizer, including system text and output allowance; utility routing does not select a smaller context from user-text size alone. The approximate packer reserves the corresponding context margin.
- **Honest failures:** a provider error after queued answer tokens preserves that partial answer as a failed turn; cancellation suppresses the private queued tail. Ollama must emit its completion marker. A failed stream after visible output cannot silently append a bundled fallback answer. Structured utility requests forward their schema and thinking constraints, and unsupported server capabilities or incomplete output fail explicitly.
- **Bounded resources and source navigation:** grammar retention is bounded instead of keeping every dynamically varying schema forever. The provided-source menu supports arrow keys, Home/End, Escape and normal Tab exit, with focus restored appropriately. These are deterministic behavior fixes, separate from language-model accuracy.

## Research and evaluation method

The [research review](2026-10-02-conflict-rag-research.md) and [implementation review](2026-10-02-conflict-rag-implementations.md) examine primary papers and upstream implementations covering conflicting evidence, sufficient context, abstention, citations, retrieval correction and evaluation. They do not justify installing another large model or treating a relevance score as an authority decision. The [evaluation design](2026-10-02-authority-evaluation-design.md) draws on RGB, ConflictBank, SituatedQA, Sufficient Context, ALCE and FreshQA to separate supported answers from safe abstention, completeness and exact passage attribution.

Eight new DEV cases and eight independently reserved cases each contain five answerable and three abstention cases, split evenly between German and English. They cover unresolved numbers, approved replacement, an unapproved later proposal, scope/time differences, equivalent units, missing evidence, code boundaries and agreement. The older heldout corpus has already informed development and is therefore a reused regression set.

Candidate E was explicitly frozen before reserved publication at **10:48:56 UTC on 2 October**: the recorded E manifest, existing 4B Q4_K_M model, 8192 context, assessment/rerank off, one run without warm repeats, 300-second questions, continuation only after definitive settled errors, and isolated idle auto-lock off. No later original or reserved result may drive production tuning under this evaluation claim. The original reserved manifest and 15 sources were published without changing any of their 16 locked hashes. Their canonical lock seal remains `e18ae81aeeb0ff40b588c78824db44e9605b317ee50651a68c9d8e8d29008963`. All 17 files including the lock also survived an isolated Git staging/checkout round trip with `core.autocrlf=true`; explicit LF attributes and formatter exclusions preserve those bytes. The detailed local proof is `out/optimization-20261002/reserved-publication-proof.json`.

Semantic reviews are made by separate assistant agents reading the actual supplied passages and answers; they are not human-expert review or self-grading by the local Qwen model. Regexes and source-ID membership are diagnostic aids, not entailment proof. A correct value with a wrong supporting passage, a correct final bullet after an incorrect opening, and an accurate quotation that fails to answer the question do not earn full credit. All failed, cancelled and timed-out observations remain in the record.

## Why the second pass stays disabled

The fixed-order experiments deliberately varied two open DEV questions through A/B, B/A and duplicated-source variants. They exposed invalid structured output, copied evidence that omitted the relevant fact, invented authority and duplicate-sensitive false conflict decisions. A later unit-based version handled those two small controls correctly, but that did not generalize to the application context containing ten passages.

In the full D run, all eight assessments executed with ten supplied passages. Three were classified unresolved, four compatible and one insufficient. The newer unapproved proposal was falsely treated as unresolved despite a still-effective approved rule. The unresolved ledger answer quoted nine passages, seven irrelevant. The code response quoted the two branches without computing the requested result. Verbatim evidence proves text presence, not a correct relationship or a useful answer.

Median D assessment time alone was 73.844 seconds; median whole-request time 162.956 seconds and first-visible time 112.1975 seconds. Those times include the observed local resource path and are not acceptable evidence of a speed improvement. [The decision analysis](2026-10-02-assessment-decision-boundaries.md) preserves the failed alternatives. `LOKLM_EVIDENCE_ASSESSMENT=1` remains explicitly experimental and is not recommended for daily use; there is no user-facing toggle or claim-validation badge.

An additional out-only diagnostic completed two selected, already observed controls in `out/optimization-20261002/thinking-diagnostic-1128/raw.json`. Both ended normally. The third prepared pump-count case was intentionally unrequested under the time limit, not failed or silently missing.

This probe used only each required source pair and a shorter separate prompt, with no matched nonthinking control. A matched-control script was prepared but never executed. The observations cannot isolate thinking from prompt, evidence or sampling changes. They are development evidence, not another fresh reserved result, an end-to-end production test or a promoted default. No hidden thought text was extracted, and no production or frozen-report change followed. The mixed result does not demonstrate that a thinking-mode switch solves the problem.

The native observations use the existing Qwen3.5-4B Q4_K_M on a GTX 1050 Ti with 4 GB VRAM, actual 8192-token context and 14 GPU layers; CPU offload remains part of this bounded hardware configuration. Embedding uses the GPU. The calibration explicitly disables reranking, multi-query expansion, routing and whole-document fallback while exercising real retrieval, packing and generation. This matches the intended no-reranker hardware case, but does not itself test every automatic policy or optional retrieval path. It does not represent larger GPUs, fully GPU-resident inference or arbitrary Ollama models.

Later application runs record a 300-second per-question limit instead of the baseline's 180 seconds, and no warm repeats. The isolated test vault disables idle auto-lock because API-only runs generate no ordinary user activity; the production security default is unchanged. C's original cancellation remains recorded. Results that exceed the original timeout are not silently relabeled as having met that earlier limit.

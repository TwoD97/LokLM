# Conflicting evidence in local RAG: research and experiment design

Research date: 2026-10-02. Starting application revision: `40fe513`. This review separates published findings from LokLM's measured prototype results. Research did not change frozen fixtures, model files, or user documents; the subsequent authorized prototypes are described below. Technical evidence comes from authors' papers, conference publications, or official project repositories; results are reported for their original settings. Forum observations are separately labelled anecdotes.

## Recommendation

**The final E regression still does not demonstrate reliable automatic authority resolution on this local 4B model.** In the reused Orvo case, both conflicting drafts were actually supplied and explicitly lacked approval or supersession, yet the answer invented documentation rules making draft B authoritative. A separate answer returned the correct inspection count but cited the plan introduction instead of the supplied numeric table. Do not describe the original overconfident-conflict problem or exact passage attribution as fixed. The independently useful protocol, context-budget, prompt-synchronization and runtime corrections remain valid; they do not turn generated claims into verified facts.

The investigated candidate is a bounded evidence assessment before final generation, using the already resident chat model, followed by a source-attributed comparison when it identifies an unresolved disagreement. The model selects numbered source units; application code reconstructs intact original windows with adjacent context and validates source membership. Keep both sides visible. Do not convert relevance, document repetition, a later date, a filename, or the model's confidence into proof of authority. **Keep the guard off by default:** app-level results already show irrelevant quoted evidence and a false abstention on an explicitly authorized current value, despite promising two-source controls.

A check that an answer is supported by just one passage cannot establish whether the competing passages were considered. An unresolved comparison can instead be rendered from genuine source text without a second generation choosing a winner. This remains an experiment: a small model can miss conflicts, infer the wrong scope, misread negation, or select incomplete evidence. Local failed alternatives below demonstrate those limits. No detector superiority or reliable default is inferred from the papers or the two-topic order probes; prompt-only and guarded app answers require separate evaluation. The output must not be labelled a verified answer.

## The local failure and available implementation seams

The [October reused held-out review](../../tests/evals/native-calibration/reports/optimization-20261001-heldout-regression/REVIEW.md) records the important distinction: all nine answerable cases had correct facts and exact supporting citations, but one of three uncertainty cases asserted a definitive deadline despite two conflicting unapproved drafts in the supplied context. Its citation supported one draft's date, not that draft's authority. Retrieval had supplied the competing evidence; simply retrieving more or turning on a reranker does not address that observed failure.

At the starting revision, the English and German prompts already required reporting unresolved disagreements and accepting approval/supersession only when explicitly supported. They also emphasized a single final answer and avoiding alternative interpretations. The current [prompt.ts](../../src/main/services/llm/prompt.ts), `buildSystemPromptEn` / `buildSystemPromptDe`, removes that competing instruction and clarifies scope and negated/pending approval. Retained observations do not establish any one sentence as the cause; the prompt-only app control is evaluated separately.

[QAService.ts](../../src/main/services/qa/QAService.ts) prepares the actual answering context after retrieval, packs evidence, computes `fedHits`, publishes their source IDs, and then calls `ask`. An assessment must account for the exact evidence that survived packing. Checking the larger pre-pack retrieval set while generating from a smaller set would conceal evidence loss. Summary-only context requires separate handling because a generated summary is not an original source passage.

[LlmProvider](../../src/main/services/providers/types.ts) exposes `generateRaw` with `jsonSchema`, `plannedContextTokens`, cancellation, a task-specific system prompt, and completion checks. Bundled grammar constrains syntax; Ollama receives the schema through its structured-output API. Source and semantic validation remain necessary for either provider. Budget the actual assessment instructions, source-unit input, output allowance and context reserve; the separate grammar schema is not serialized into the model's token prompt. Retain native exact-context checks. Do not add another model or introduce a chat → embedding → chat handoff merely to inspect already retrieved text.

## Primary evidence

### 1. Conflict type matters, but detecting it is not solved

[DRAGged into Conflicts, Cattan et al. (2025), §§2–5](https://arxiv.org/html/2506.08500v2) distinguishes compatible/complementary information, opinions, outdated information, misinformation, and no conflict. Its 458-query expert-annotated benchmark evaluates response behavior separately from grounding and answer recall. A two-stage classify-then-answer pipeline improves aggregate behavior, but the strongest reported category classifier reaches only 65.3% accuracy. Tested open models are Gemma 3 27B and Qwen 2.5 72B; there is no local 4B validation. The per-category table also shows a decrease on no-conflict cases for the illustrated model.

**Transfer:** separate detection, resolution, and answer quality; include non-conflict controls. The paper's treatment of fresh web facts does not imply that a newer internal draft supersedes an approved earlier document. [Official dataset repository](https://github.com/google-research-datasets/rag_conflicts) exposes source text, date, and conflict labels; it was archived in August 2026 and displays Apache-2.0 licensing. No dataset material was copied here.

### 2. Blanket conflict hints can create false conflicts

[FaithEval, Ming et al., §§3–5](https://arxiv.org/html/2410.03727v2) separately evaluates unanswerable, inconsistent, and counterfactual contexts. Inconsistent examples combine passages that individually support different answers. Models often handle each passage alone much better than the combined context. Additional conflict instructions help awareness but hurt ordinary-context accuracy for the two strong models in its controlled comparison. The study therefore supports evaluating refusal and conflict behavior independently of normal QA performance.

**Transfer:** retain ordinary questions, compatible figures, irrelevant distractors, and explicitly resolved revisions in every comparison. Do not enable a mechanism based only on the number of conflict cases it catches. Its synthetic perturbations and older tested models do not predict this quantized model's success rate.

### 3. Recent inter-context benchmark supports unfamiliar entities and negative controls

[Ragability, Gross et al., LREC 2026](https://aclanthology.org/2026.lrec-1.182.pdf) replaces real entities with invented ones to reduce interference from model memory. Its 53 manually authored entries combine conflicting, compatible, and general-information contexts into 1,060 test combinations. The seven models include Llama 3 8B and six proprietary models, not this local 4B. It finds a gap between explicit contradiction detection and answering content questions. A contradiction hint improves contradictory cases while reducing performance on non-contradictory ones.

**Transfer:** use independently authored entities, paraphrases, and question forms; test content answers, not just a yes/no detector. Its short constructed contexts and limited model set do not establish production reliability. The [dataset card](https://huggingface.co/datasets/ofai/RagabilityCorpus) declares CC-BY-SA-4.0, separately from the proceedings page's CC-BY-NC-4.0 paper license. No data was imported.

### 4. Small models are affected by repetition and source labels

[Whose Facts Win?, Schuster et al. (2026), §§3–6 and appendices B/I](https://arxiv.org/html/2601.03746v2) includes Gemma 3 4B and Llama 3.2 3B. In controlled synthetic table conflicts, source labels influence preference; repeating the same evidence can reverse those preferences even without another independent source. The experiments vary table/answer order. Credibility prompting does not consistently restore the original hierarchy; a fine-tuned model is a separate intervention.

**Transfer:** test reversed evidence order, duplicate passages, and asymmetric source counts. Do not implement majority voting over chunks or treat a title such as “official” as authenticated provenance. These are source-preference experiments, not proof that the preferred source is true. [Authors' repository](https://github.com/JaSchuste/llm-source-preference).

### 5. Abstention needs calibration, not an invented confidence cutoff

[Sufficient Context, Joren et al., ICLR 2025, §§3–5](https://arxiv.org/html/2411.06037v2) distinguishes contextual sufficiency from answer correctness and entailment. Its selective-generation experiment combines a sufficiency signal with self-rated answer probability using a fitted logistic model. The efficient autorater in that experiment is FLAMe 24B, with context divided into 1,600-token chunks. It is not a free confidence field produced by a generic 4B model.

**Transfer:** report answer coverage and error among answered cases, plus false abstention. Do not borrow a published threshold or turn a same-model confidence number into a correctness percentage. A rule accepting sufficiency when any passage supports an answer is especially insufficient for unresolved cross-source conflict. [Official code/prompts](https://github.com/hljoren/sufficientcontext).

### 6. Credibility filtering may discard the evidence needed to see a conflict

[CONFACT, Ge et al., IJCAI 2025, §5 and limitations](https://arxiv.org/html/2505.17762v1) studies evidence from media sources with credibility annotations. Supplying source background at generation helps in its setting; credibility-based filtering/ranking can degrade results by removing counter-evidence. The authors acknowledge static credibility assumptions, imperfect automated background estimation, and annotation bias.

**Transfer:** do not add an arbitrary authority weight to existing retrieval scores. Internal source authority needs explicit relevant evidence or user-established metadata, not a generated publisher reputation. This news fact-checking setup does not validate automatic approval/supersession reasoning for private business documents. [Official dataset](https://github.com/zoeyyes/CONFACT).

### 7. Conflict summarization is relevant; the complete methods are too expensive to assume a drop-in win

[CARE-RAG, Chen et al. (2025), §§2–4 and limitations](https://arxiv.org/html/2507.01281v1) builds a conflict report from retrieved and model-derived evidence using a distilled Llama 3.2 3B detector. Its full method also performs multiple generation/refinement stages and evaluates on repaired benchmark answer sets. The paper explicitly notes additional inference overhead and dependence on detector quality.

**Transfer:** a compact evidence report is a useful architectural hypothesis; the reported improvement cannot be assigned to one untrained extraction pass. Do not add model-generated background knowledge to LokLM's document-only evidence or download/train a specialist in this sprint.

[MADAM-RAG / RAMDocs, Wang et al., COLM 2025, §§3–5](https://arxiv.org/html/2504.13079v2) isolates evidence per document, then uses multiple debate rounds and an aggregator. Its tests cover mixed ambiguity, misinformation, noise, and imbalanced support, using 70B/72B models and GPT-4o-mini. The strict metric requires all valid answers without misleading additions. This motivates retaining minority alternatives, but per-document agents and repeated debate are a poor initial latency fit for one local GPU. [Authors' code/data](https://github.com/HanNight/RAMDocs).

### 8. Cheap entailment is useful, but solves a narrower problem

[MiniCheck, Tang et al. (2024), §§6–8](https://arxiv.org/html/2404.10774v2) trains specialized document-support classifiers, including 355M and 770M variants, and evaluates on LLM-AggreFact. It provides evidence that narrower checking tasks can use smaller models; its cloud-cost comparisons are not desktop latency estimates. The authors explicitly state that training is English-only and the benchmark does not require evidence spread across distant text or multiple documents.

**Transfer:** a future checker could help detect unsupported claims. It cannot establish that a supported claim is the uniquely authoritative answer when another source disagrees. Separate model availability, German performance, runtime compatibility, licensing, and the extra GPU handoff would need evaluation. [Official repository](https://github.com/Liyan06/MiniCheck).

### 9. The same model family still exhibits evidence-order failures

[When Evidence Conflicts, Han et al. (2026), §§3–5](https://arxiv.org/html/2605.14115v1) evaluates six models on 920 biomedical yes/no questions with supporting and contradicting evidence. It includes Qwen3-4B-Instruct-2507. Reversing the same evidence pair flips 16.7% of that model's answers in the reported order test, while aggregate confidence changes little. Its abstention experiment trains a condition-specific error detector using uncertainty and semantic features; it is not an untrained confidence cutoff.

**Transfer:** order reversal is a necessary control even for this model family, and confidence should not substitute for conflict handling. The domain, binary next-token decision, and model execution differ from quantized, free-form, bilingual, citation-bearing LokLM answers. Neither its accuracy nor its trained detector thresholds predict local performance.

### Other reviewed directions

[ConflictRAG (2026)](https://arxiv.org/html/2605.17301v1) uses trained embedding classifiers, selective LLM refinement, and LLM-extracted credibility criteria. Its own diagnostic score favors explicit conflict modules; model-generated authority/recency scores and classifier thresholds are not transferable defaults. Its generation comparisons use remote large models, not this local profile.

[TCR, AAAI 2026](https://ojs.aaai.org/index.php/AAAI/article/view/40740) uses dual contrastive encoders, self-answerability signals, and a learned soft prompt. It is a training/runtime integration project despite the publication's plug-and-play description; the abstract does not validate an ordinary prompt change on an existing GGUF.

[Intrinsic self-correction study, Huang et al., ICLR 2024](https://arxiv.org/abs/2310.01798) finds that self-correction without external feedback can fail or reduce reasoning accuracy. This is not a direct test of source-grounded conflict checking, but supports avoiding repeated “check again” loops as an assumed independent verifier.

## Firsthand forum reports: test leads, not benchmark evidence

In the [local legal-document adaptation discussion](https://www.reddit.com/r/LocalLLaMA/comments/1uolb4y/local_llm_for_legaldocument_adaptation_keeps/), the author reports altered citation identifiers despite correct citations already being present in a Portuguese source template. Replies propose preserving immutable citation strings and validating generated references outside the model. This motivates exact identifier/span tests and separating displayable source membership from claim support. The thread provides no controlled comparison supporting its model, quantization, or zero-error claims; none of those claims is adopted here.

In [Document comparison RAG, the struggle is real](https://www.reddit.com/r/LocalLLaMA/comments/1cn659i/document_comparison_rag_the_struggle_is_real/), the author reports confusing a reference document with the document being evaluated. Other practitioners describe revision discrepancies, unreliable extracted structure, and experiments with explicit document boundaries or per-document extraction. Those observations motivate source-identity, scoped-authority, and boundary tests. They do not establish that vector storage inherently merges document identities, that delimiters guarantee comprehension, or that GraphRAG is required. LokLM's source IDs and supplied-context traces allow these proposed failure modes to be checked directly.

These anecdotes identify practical test cases; the technical reliability argument remains grounded in the primary papers and local measured outcomes. No forum performance percentage or hardware recommendation is used as an expected application result.

## Experiment design and current candidate

The following is LokLM's bounded engineering design, not an implementation or performance guarantee claimed by any paper above.

1. Run at most one assessment after retrieval and context preparation. Use the exact packed passages, the literal question, and source IDs. If a complete assessment cannot fit its context/output budget, record incomplete coverage rather than silently omitting sources and returning “no conflict.” A source may be irrelevant, compatible, conflicting, or insufficient; not every differing number is a contradiction.
2. Present all eligible source passages as numbered units and request up to three increasing unit IDs per passage, with an explicit empty array for an unselected passage. Require the model's selected value and relevant conditions/approval status rather than only headings. Reconstruct one original first-to-last window, including intervening and adjacent units. Selection remains a model hypothesis; accounting for every source key does not prove careful reading.
3. Validate source/unit IDs, uniqueness/order, complete parsing, distinct original selected texts, and display bounds. Retain original source bytes for display. A valid window proves presence only; it may still miss distant qualifiers. In particular, a quote containing “not approved” must never become code-certified approval merely because a generated label says approved. Literal-copy checks do not establish source independence or authenticity.
4. For detected unresolved conflicting answers, prefer a code-rendered comparison with both exact source citations and a narrow statement that the supplied evidence does not establish one answer. Avoid another model pass that can erase the alternatives. Distinguish this from a claim that the whole library contains no resolution.
5. Explicitly resolved revisions and compatible facts remain necessary positive controls. Preserve the exact authority sentence and its target/scope; document recency alone is insufficient for an internal draft. If the model cannot resolve authority reliably, present the competing source statements as statements rather than inventing a winning authority.
6. Keep cancellation, terminal persistence, language handling, and current GPU ownership. Emit a clear preparation stage without prematurely streaming an answer that later needs retraction. Measure the added prefill/output tokens and first-visible latency. One extra pass avoids another model download but is not free.

The first opt-in prototype deliberately caps assessment at twelve complete packed chunks, 160 characters per exact span, 640 characters across evidence spans, and 384 generated tokens. An initial eight-chunk limit was corrected before native prototype testing because the actual supplied-context events contained ten passages; final cited-source counts were not a coverage measure. The compact output maps every supplied source ID to its exact quote or an explicit empty string. Missing, unexpected, or overwritten duplicate keys are rejected. It skips unsupported/oversized inputs instead of assessing a hidden subset. These bounds may miss useful long qualifiers or broad questions and must be reported as coverage limits. A source span being an exact substring does not prove it retained all necessary qualifiers. Quoted source markers, math, list/code syntax, and explicit Markdown links must remain visible text; only program-owned source markers become citations. GFM can still make ordinary quoted URLs/email clickable under the existing external-link policy. Actual Markdown renderer tests, not just string assertions, check this boundary. Resolved, compatible, and insufficient classifications are not code-certified answers. On the current 4 GB runtime, raw generation shares the chat session; this adds prefill and generation work without requiring a second model residency change.

Do not ship uncalibrated confidence scores, regexes tied to known fixture names, unconditional refusal on every numeric difference, silently repaired citations, or a loop that retries until the preferred answer appears. Learned detectors, specialist models, conformal/calibration guarantees, and multi-agent debate require separate data and resource work.

### Local prototype counterevidence collected during this review

These are fixed-context diagnostic probes on two development questions, not held-out results or whole-application answer scores. Original artifacts are retained under `out/optimization-20261002`.

- The initial quoted-span probe produced incomplete JSON. Runtime inspection found that Qwen's automatically opened thought segment could consume the first grammar-constrained response token before the zero-thought budget was applied. A public wrapper configuration change corrected that native boundary; output repair was not used.
- With the wrapper corrected, the quoted-span control produced valid JSON and useful literal spans for both questions. However, the approved-versus-proposed example assigned backwards resolution metadata while quoting text that explicitly denied approval. This is concrete evidence that exact quotation and valid structured fields do not certify authority. The result was an assessment failure, not an observed final-answer choice: QA did not promote that resolution field into a winner.
- Source-unit V2 reduced generated copying but rejected both controls because the model selected noncontiguous IDs. One of those selections also omitted the operative approved value. V3 preserved a single whole window across selected IDs, including intervening units and neighbors, and was initially left unmeasured; the V2 rejections were not retrospectively converted to passes.
- Whole-passage V4 avoided within-passage clipping and returned the expected relationship label in all eight order/duplicate probes. It nevertheless failed all four unresolved-conflict probes: selections omitted one or both opposing sources, and duplicate variants selected only copies of one side. The independent requirement for different whole texts correctly rejected those apparent two-source results. The four compatible-path classifications were usable, but do not establish final-answer correctness. Observed assessment time ranged from 15.649 to 22.579 seconds (eight-observation median 18.1305 seconds); these timings are not an isolated causal comparison with earlier prototypes.

V5 asks first for the relationship and requests involved source IDs only for an unresolved comparison. It keeps all input passages, reconstructs whole selected passages, and rejects missing/unknown/duplicate IDs, same-side copies and oversized unresolved displays. Compatible/insufficient paths return no unused source-selection judgment. Native V5 produced valid comparisons for the four unresolved-conflict perturbations, but falsely called the answerable approved-versus-proposed case unresolved in three of four perturbations. Only the variant repeating the current approved source returned compatible. These are repeated versions of two questions, not eight independent test questions. The false-refusal result prevents default adoption despite syntactically valid output and exact quoted provenance. Whole-passages also increase reading burden and may leave requested arithmetic/code derivations incomplete.

The previously prepared V3 unit-selection candidate was then measured without changes. All eight original-parser results had the expected relationship: four unresolved comparisons retained both counts and their missing-approval context; four approved/proposed controls remained compatible. This is still only two underlying topics. In two compatible controls the selected proposal window omitted the proposed value and a key authority sentence, although ordinary answer generation still receives the original full passages. Median assessment time was 30.6885 seconds, with a separate 41.426-second initial load. No accuracy or latency generalization follows from this small diagnostic set.

V3 was selected for the opt-in application helper, pending broader end-to-end review. Its system prompt and inference schema are unchanged from the frozen experiment. Production validation additionally requires distinct original selected passage texts, preventing different windows from two copies of one passage from masquerading as competing evidence. Display limits apply only to unresolved comparisons; compatible/insufficient windows are not promoted into answer guidance. Exact duplicate displayed windows are grouped once with all original program-owned citations; assessment input is not deduplicated. These refinements do not change the eight short native controls' outcomes. The default remains off; quote selection, source authority and requested calculation completeness still require independent review.

An offline parity check compared all eight captured V3 inference payloads (prompt, system prompt, schema and output cap) and parsed observations with the integrated helper: they match exactly. Focused integration validation passed 76 tests across eight files covering planning, parsing, display, cancellation, prepared context and pinned-context budgets; Node TypeScript and scoped ESLint checks also passed. Those checks establish implementation consistency, not model correctness on unseen evidence.

### Full retrieval context exposed a failure absent from the two-source probes

In the first guarded app-level DEV case (`authority-20261002-assessed-d-dev`, DEV01), retrieval supplied ten source passages. The assessment selected nine. The displayed comparison retained the correct museum counts, 980 and 1040, and both missing-approval qualifications, but also included seven unrelated passages about shuttle capacity, code branches, sensor mass and laboratory retention. Their text and source IDs were genuine; they were not relevant evidence for the museum question. The generic unresolved-comparison introduction and long blockquote output did not make that distinction for the user. The assessment stage alone took 75.618 seconds on this observation.

This is a relevance and answer-presentation failure, not an invented final museum total or a fabricated quotation. It demonstrates why real retrieval slates, distractors and end-to-end answers must be evaluated in addition to clean two-source classification controls. Exact source membership, complete JSON, source ordering tests and eight correct diagnostic relation labels did not establish useful app behavior. The result argues against enabling the guard by default; no source/entity-specific filter or new threshold was introduced to repair this known case. Subsequent app-level results must be retained, including false abstention and calculation incompleteness.

The guarded DEV03 answer then falsely abstained on the currently authorized shuttle capacity. It quoted both the approved 12-passenger certificate and the unapproved 18-passenger proposal, including the explicit absence of an approved replacement, but still presented them as unresolved. The prompt-only C answer correctly distinguished current authorization from the later proposal. This is an answerability regression, not just a longer response or incomplete citation. Guarded DEV02, by contrast, correctly explained the 21-day approved supersession with both revision sources; that positive outcome is retained. These mixed results reinforce a default-off decision without claiming all guarded answers fail or that the prompt-only model is universally reliable.

The completed eight-case D review records four of five answerable cases fully supported and one of three abstention cases complete. The other abstentions preserve the unresolved decision but are partial: DEV01 includes unrelated material, and DEV07 reproduces both code branches without evaluating the requested `fee(5)` results. The latter is safer than inventing a production winner but leaves the needed 7-versus-3 distinction implicit in unevaluated code. [The complete D review](../../tests/evals/native-calibration/reports/authority-20261002-assessed-d-dev/REVIEW.md) retains successful unit conversion, missing-phone-number handling and bilingual agreement alongside these failures.

The same-build D prompt-only follow-up was not a clean guard-on/off comparison: its automatic profile resolved to `full`, while guarded D resolved to `lite`, even though both used the same 4B weights, an actual 8192-token window and 14 GPU layers. The pre-fix profile mapping gives these two profiles different system-prompt depth instructions. Same-language updates previously returned early, allowing the initially selected prompt to remain in place after actual capacity was known. C also used `lite`; native KV types vary across these runs. Comparisons retain these configuration differences, rather than attributing every answer or timing difference to the assessment. No earlier artifact is relabeled as a matched experiment.

Candidate E fixes this application-state inconsistency: a Full-profile load with a known positive context of at most 8192 tokens uses the same standard document-answer depth as Lite's 4B. Larger or unknown Full windows, XL, and the legacy Lite 2B behavior retain their existing mapping; the code-workspace depth increase still applies afterward. The service clears stale capacity before a new load and synchronizes the effective system prompt after loading/restoration and before answering, even when the requested language is unchanged. Direct callers restore parked chat before selecting the prompt/budget. Prompt acknowledgements are serialized, invalidated by a new load result, and rejected after session retirement; a failed synchronization prevents generation with a stale prompt. This changes prompt consistency, not the model's ability to establish authority. It introduces no source-text logging and no experimental-assessment default change. Focused tests cover late acknowledgements, changed capacity, retry after synchronization failure, cancellation, retirement and preserved profile/code behavior; E's native answer checks remain separate evidence.

E's two selected development controls then returned a supported retention revision answer and correctly computed both code results while withholding an unsupported production winner. Both observed runs resolved to Lite, so they do not separately demonstrate the Full-at-8K branch natively. Six other new DEV questions were not requested in this selected check. The [E control review](../../tests/evals/native-calibration/reports/authority-20261002-prompt-e-controls/REVIEW.md) records the actual variable KV types and timings; these two observations are not a general code-reasoning or authority guarantee. The subsequent original-heldout run is reused regression evidence, and the separately reserved suite remains a distinct final evaluation.

Independent cross-review of E's actual reused original-heldout answers confirmed two correct code results and the still-material authority failure. Case 08 answers 60 seconds in one German sentence; supplied/cited `5:8` implements `min(3 * 20, 90)`. Case 11 answers 0 seconds with a correct explanation of the `attempt <= 0` branch, in one English sentence citing the same complete function. Case 10 instead asserts a final 2027-05-15 deadline and invents a documentation-rule replacement of draft A. Supplied `3:6` says 2027-05-08 and explicitly lacks approval/supersession; supplied `4:7` says 2027-05-15 and explicitly lacks approval or any replacement statement. Both have issue date 2027-04-01. Citing `4:7` supports one draft's date, not finality or authority, and does not attribute A's date. Correct ISO formatting does not mitigate the semantic failure. Case 02 separately returns the correct 156 inspections but cites `2:4`, a title/approval passage, while the numeric fact is in supplied `2:5`. These are successful transport completions, not missing-context or timeout failures. The final implementation stays frozen; these observations are retained rather than prompting another known-case-specific fix. The broader [final reliability report](2026-10-02-rag-reliability.md) keeps the reused regression separate from the reserved evaluation.

Retaining the single `LOKLM_EVIDENCE_ASSESSMENT=1` hook is justified as explicit developer-only diagnostic scaffolding for reproducing the actual retrieval/packing/UI boundary. It has no settings toggle and is off unless expressly enabled. It is **not a shipped answer-quality improvement** and should not appear as a verification feature in product claims. The failed full-context observations and disabled-path regression must remain visible. If no concrete follow-up evaluation is planned, a later simplification should move it into a versioned test-only integration patch rather than accumulating production variants or leaving the only reproducible implementation in ignored `out/` files. Native wrapper/context/structured-output correctness fixes are independently useful and should be assessed separately from this unsuccessful default candidate.

### Lexical-query audit: real noise, insufficient evidence for a new retrieval default

The D01 native retrieval trace provides a useful distinction between lexical pollution and the assessment's relevance error. `WorkspaceDb.toMatchQuery` ORs all terms, including grammatical words; the no-reranker path accepts any lexical hit regardless of its BM25 magnitude. All fifteen fixture documents therefore receive a lexical vote. Seven have scores around one millionth, while the two relevant ledger chunks score 12.238. However, thirteen of the fifteen dense scores already exceed the existing 0.25 floor. Every finally supplied passage is above it: the two ledger chunks score approximately 0.843 and 0.844, while the unrelated supplied passages range from 0.269 to 0.339. Removing a lexical vote alone cannot remove those dense-eligible passages while retaining the same ten-result policy.

A small offline, in-memory SQLite FTS5 replay used the actual native `documents[].chunks[].text`, an empty `context_prefix`, and the production `unicode61 remove_diacritics 2` tokenizer. It reproduced all eight D lexical rankings and scores exactly before any experimental filtering. A deliberately small English/German function-word set then reduced lexical result counts across DEV01–08 from `15,15,7,15,8,6,2,5` to `15,15,2,15,4,5,2,4`. Negation, domain terms, dates and identifiers were retained. In D01 the shared year 2028 still matched every document, so the count remained fifteen and the unrelated tail was merely reordered. Both ledger passages remained first. Replaying equal-arm RRF and the existing native floor against unchanged measured dense scores still yielded ten candidates for seven queries and nine for DEV06. This final count is a fusion/floor replay, not a rerun of every downstream heuristic or of answer generation.

This supports a future scoped lexical-query hygiene experiment, not a claim of improved answers or a repair for the guarded D01 dump. No production stopword list, cosine threshold, top-K, semantic query, or library-search behavior was changed. In particular, relative-score pruning could discard less similar but essential minority counterevidence; the observed dense-score gap is not an authority signal or a calibrated universal cutoff.

### Implementation review boundaries

The optional stage retains the provider captured for the current turn and assesses only the exact packed original hits, after actual context preparation. It reuses the existing provider destination/consent policy; no new upload endpoint or model is introduced. Source contents are not written by the stage's diagnostics, and parsing/provider failures become a generic user-facing error. Provider admission checks reject an already aborted signal; completion and yield-boundary checks suppress late comparison output. The complete assessment prompt/output allowance is budgeted separately and native exact-context validation remains active.

Coverage remains deliberately limited: at most twelve passages, at most thirty-two intact units per passage, up to three selected units per source, and bounded unresolved display windows. Packed history and generated-summary preambles bypass this experimental stage; a turn whose history was entirely omitted by packing can still be assessed against the same history-free inputs used for final generation. Compatible and insufficient are fallible model judgments and do not certify the subsequent answer. Intact code/table units do not execute code or derive an arithmetic answer; quoted evidence can be faithful yet incomplete. None of these structural/privacy checks establishes semantic correctness or protection against all source-level prompt injection.

| Newer draft after approved release            | Do not assume the newer draft overrides the release.                                 |
| Historical versus current observations        | Honor the requested as-of period; avoid a false conflict.                            |
| Different entity/site/product                 | Keep identities distinct; no conflict from unrelated numbers.                        |
| Different unit or precision                   | Recognize compatible conversions/ranges where justified; do not remove qualifiers.   |
| Planned versus actual, minimum versus maximum | Preserve attribute/modality; do not combine unlike quantities.                       |
| Partial/no evidence                           | Say what the supplied context lacks without inventing a stronger process claim.      |
| Reordered/repeated sources                    | Same substantive decision; repeated passages are not independent authority.          |
| Authority wording with negation or conditions | No approval inferred from negated, proposed, or conditional approval.                |
| Ordinary single-source, arithmetic, code      | Retain useful answers, citations, requested language/format, and acceptable latency. |
| Long/partially packed evidence                | Expose assessment coverage limits; never equate unchecked text with agreement.       |

Grade separately: retrieval/packing coverage, assessment coverage, conflict false negatives, false conflicts, unsupported authoritative selection, supported answer completeness, exact passage attribution, false abstention, and runtime/cancellation. Mechanical quote/ID checks cannot replace independent semantic review. Report conventional medians, output/prompt tokens, actual context/KV/GPU layers, and cold versus warm state. An error-free small diagnostic set is still not a general reliability guarantee.

## Adoption and licensing boundary

No third-party code, prompts, trained weights, or benchmark passages were imported by this review. Paper access does not grant a blanket right to redistribute every linked dataset or its underlying web articles. If a later implementation adopts code/data, check the exact artifact's license and pin its revision. Prefer original small fixtures that cover the researched failure families; keep public benchmark results and LokLM's own measurements distinct.

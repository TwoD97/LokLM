# Bug audit — 5 October 2026

This audit starts from `fb357a0` and addresses reproduced document, folder-sync and request-lifecycle failures. It does not establish that every application bug is fixed, or that the local model reliably resolves conflicting evidence. Validation and its limits are recorded below.

## Confirmed fixes

| Area                  | Reproduced failure                                                                                                                                                                           | Change and regression coverage                                                                                                                                                                                                                                  |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Document refresh      | Replacing a file with different-length content while preserving its indexed timestamp returned `unchanged`.                                                                                  | The metadata shortcut now also requires matching byte size. A real temporary-file test restores the old timestamp and verifies reindexing and the new hash. Same-size edits with an intentionally unchanged timestamp remain outside this cheap metadata check. |
| Folder operations     | Concurrent additions overwrote a root; removing a root during a scan could leave a subsequently imported document orphaned.                                                                  | Scans and root mutations use the same per-workspace queue. Deferred-operation tests reproduce both races. Root edits can wait for an active scan; different workspaces remain independent.                                                                      |
| Folder removal errors | Cleanup failure was caught after disconnecting the root, so removal reported success while indexed copies remained.                                                                          | Cleanup and index-selection errors reach the caller; the root remains connected until cleanup succeeds and can be retried. This is ordered recovery, not a transaction spanning SQLite and the vector store.                                                    |
| Watcher ownership     | An old `start()` folder read could resolve after removal or `stopAll()` and revive obsolete watchers.                                                                                        | Pending starts lose ownership when watchers are stopped or replaced. Deferred snapshot tests cover removal and stopping before attachment.                                                                                                                      |
| Platform paths        | Case-insensitive prefix checks could delete `/data/Reports` documents while removing `/data/reports` on Linux.                                                                               | Containment uses platform path semantics with parent/sibling/absolute-path bounds. POSIX case distinction and Windows case, drive and sibling behavior have focused regressions.                                                                                |
| Answer streaming      | A consumer closing its iterator could leave generation running. Rejection while paused at a yielded token could be unobserved; cancellation between queued chunks could expose a later tail. | The iterator owns a generation controller, observes producer settlement before yielding, stops accepting late callbacks and checks cancellation while draining. Tests cover early closure, immediate rejection and queued-token cancellation.                   |
| Provider cancellation | Retiring a session suppressed results but could leave remote requests running; a cancelled query could continue embedding or reranking.                                                      | Session and caller signals reach provider operations. Shared query embeddings cancel the producer only when their final consumer cancels. Native batch work still finishes at its existing boundary.                                                            |
| Provider selection    | A captured reranker could follow a later provider replacement.                                                                                                                               | Reranker wrappers retain their selected and fallback providers. Tests replace the provider during an operation and verify cancellation and session retirement do not dispatch stale fallback work.                                                              |
| Ollama output         | An empty completed answer could appear successful. Reranker prose, out-of-range numbers or incomplete responses could be converted into plausible scores.                                    | Empty answers fail explicitly. Reranking requires a completed response containing one finite number from 0 through 1; invalid scoring leaves retrieval's hybrid order intact. Cancellation prevents subsequent passage requests.                                |

Two additional native-provider failures were reproduced and corrected. A context-overflow retry could append a replacement answer after part of the first answer was visible; retries are now limited to the pre-output case. Reranker unloading skipped model-weight disposal when context disposal failed; it now attempts both releases. Their focused tests first demonstrated the incorrect replacement success and missing weight disposal, then passed with the fixes.

## Existing protections, not new fixes

The organizer's durable revision checks, serialized writes and draft preservation were reviewed without a confirmed new defect. The Library view already remounts its content by workspace ID, so the suspected stuck Retry state across workspace navigation was not an application bug. The native `llmLoad` failure cleanup was also already present; additional regression coverage must not be presented as a newly implemented cleanup path.

## Dependency findings

An update to `http-cache-semantics@4.3.0` is **not a demonstrated fix**. Its published `index.js` exactly matches pinned commit `b1d4bd682fbab0252985de45219f4e7497c0067c`. An isolated synthetic probe reproduces the same `max-stale` reuse of shared Set-Cookie, proxy-revalidate and response-no-cache entries on both versions; ordinary expired-cache and must-revalidate controls distinguish the cases. The advisory currently lists affected versions through 4.2.0 and no patched version. Moving outside that version range would conceal the finding without repairing the tested behavior. Keep the advisory visible. See the [reviewed advisory](https://github.com/advisories/GHSA-ch52-4w7c-c8xp), [upstream report](https://github.com/kornelski/http-cache-semantics/issues/56) and [pinned source](https://github.com/kornelski/http-cache-semantics/blob/b1d4bd682fbab0252985de45219f4e7497c0067c/index.js).

The `lint-staged@17.6.0` upgrade is installed. The current Node 24 and Git 2.53 satisfy the [v17 runtime requirements](https://github.com/lint-staged/lint-staged/releases/tag/v17.0.0); [pinned configuration documentation](https://github.com/lint-staged/lint-staged/blob/48f9f4ea4b88eb605de3546e4599083de7a394b2/README.md) supports these CJS/function forms. Local probe scripts, downloaded pinned sources and results are in `out/optimization-20261005/dependency-review/`; they are diagnostic artifacts, not installed dependencies.

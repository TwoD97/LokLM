# Dependency remediation — 6 October 2026

The targeted updates and a new local Git parser patch address the reproduced Git, KaTeX and source-map vulnerabilities. They preserve the existing native bindings and all three earlier pnpm patches. They do **not** claim an advisory-free installation: the current registry audit still reports the locally patched HTTP cache package and unpatched `sprintf-js` copies. Registry version ranges alone missed a remaining Git option-abbreviation bypass, so the local patch is necessary even though the updated version falls outside that advisory's reported range.

| ----------------------------- | ------- | ------------------- | ------------------------------------------------------------------- |
| KaTeX                         | 0.16.47 | 0.18.2              | Direct renderer/CSS and every nested copy, including `rehype-katex` |
| `node-llama-cpp → simple-git` | 3.36.0  | 4.0.2               | Targeted parent override                                            |

`@simple-git/args-pathspec` also moves from 1.0.3 to 1.0.4 as required by the upgraded Git packages. No model SDK, SQLite, Electron, Mammoth or proxy-agent version changes are included.

## Upstream fixes and compatibility

The upstream Git updates block unsafe trailer configuration, included configuration paths and rebase execution flags; argv-parser 2.0.1 also recognizes the `VISUAL` editor variable. The final simple-git 4.0.2 release pins that parser version. The installed SDK uses the retained named `simpleGit` import, supported constructors, complete option names, `clone`, `removeRemote` and `applyPatch`. [simple-git 4.0.0 changes](https://github.com/steveukx/git-js/releases/tag/simple-git@4.0.0), [4.0.1 trailer fix](https://github.com/steveukx/git-js/releases/tag/simple-git@4.0.1), [argv-parser advisory](https://github.com/steveukx/git-js/security/advisories/GHSA-v5rq-49vh-5v5c).

However, exact advisory probes against argv-parser 2.0.1 still admitted `push --receive-p=…` and `push --exe=…`. A nonexistent Git binary safely demonstrated that the real simple-git boundary reached subprocess creation instead of rejecting them; no command payload executed. The new [local patch](../../patches/@simple-git__argv-parser@2.0.1.patch) corrects both published CJS and ESM entry points. It recognizes prefixes of push's receive-pack/exec options under the existing `allowUnsafePack` category and opt-in. Required push argument handling preserves literal values and genuine end markers, including attached/clustered `-o` values; optional arguments do not swallow a following token. Other commands retain their original token expansion. [Residual advisory](https://github.com/steveukx/git-js/security/advisories/GHSA-858h-whjf-mvg5), [Git's push option definitions](https://github.com/git/git/blob/v2.53.0/builtin/push.c), [Git's required argument consumption](https://github.com/git/git/blob/v2.53.0/parse-options.c).

The patch is pinned in the lockfile and preserved as LF by `.gitattributes`. Source maps remain upstream debugging metadata; the executable CJS/ESM files carry the correction. Retain this patch until a genuine upstream correction passes the same boundary tests; neither the version audit nor the absent SDK push call is sufficient evidence to remove it.

KaTeX 0.18.2 rejects inherited renderer settings and metadata that could bypass its trust restrictions after another component polluted a prototype. KaTeX does not itself create that pollution. Both the nested math renderer and the stylesheet resolve to the same package; updating only the direct dependency would leave the nested renderer vulnerable. The app does not depend on the internal CSS class names changed in the intervening releases. [Upstream advisory](https://github.com/KaTeX/KaTeX/security/advisories/GHSA-238p-pmpm-9mq7).

Source-map-js 1.2.2 bounds malicious indexed-map offsets, including cumulative nested offsets, and fixes additional amplification paths. Tests cover invalid/oversized offsets and normal mapping/text behavior through the package actually resolved by Vite's PostCSS dependency. [Upstream fix and regression rationale](https://github.com/7rulnik/source-map-js/pull/79).

## Checks performed

Installation used `pnpm install --ignore-scripts`, followed by `pnpm install --frozen-lockfile --ignore-scripts`. Both succeeded. SHA-256 hashes of three SQLite binaries and four installed SDK addon binaries (Windows ARM64, x64 CPU, CUDA and Vulkan) matched before installation, after installation and after the frozen reinstall. No native rebuild, model initialization or GPU call was performed.

[Dependency security tests](../../tests/unit/scripts/dependency-security.test.mjs) pass all 69 cases. They resolve the real SDK Git dependency, exercise local repository and bundle clones, remove the bundle remote, apply a patch, and import the SDK clone/patch modules without executing a download or build. Every fixture operation receives an isolated environment and a validated owned config: hooks/templates are empty and protocols other than file are disabled. The only unsafe opt-in for these benign fixture operations permits that owned config path. Both CJS and ESM security probes cover prefix/argument boundaries, no-spawn rejection and the existing explicit pack opt-in. Included configuration, trailer, editor and rebase cases remain covered. Source-map tests prove that the affected coverage-v8/magicast chain resolves the same patched file as the tested PostCSS consumer. An isolated child process converts a synthetic in-memory DOCX containing literal `%.101f` and `%.0g`: Mammoth preserves them as escaped Markdown data and loads neither `argparse` nor `sprintf-js`.

[Renderer security tests](../../src/renderer/src/markdown/MarkdownView.security.test.tsx) pass six new cases; all 33 existing Markdown renderer tests also pass. The actual MarkdownView/rehype-KaTeX path rejects hostile links and external images under independently polluted inherited `trust`, `default` and `processor` properties. Tests restore the original prototype descriptors, retain normal inline/display math, and verify renderer/CSS package identity. These are DOM tests, not a visual screenshot review.

The existing [HTTP cache patch suite](../../tests/unit/scripts/http-cache-semantics-patch.test.mjs) also remains green (30 cases). Its [local patch documentation](2026-10-05-http-cache-semantics-patch.md) describes the earlier audit snapshot; the current audit counts below supersede that snapshot, not its recorded historical results.

## Remaining sprintf exposure

The current `sprintf-js` advisory has no released fixed version. Bounded calls with `%.101f`, `%.101e`, `%.101g` and `%.0g` reproduce `RangeError` in both installed versions. Changing the exception type or clamping precision would neither establish a handled caller boundary nor preserve formatting semantics, so no such patch is applied. [Upstream report](https://github.com/alexei/sprintf.js/issues/237), [proposed patch still under review](https://github.com/alexei/sprintf.js/pull/238).

The production copy is `mammoth → argparse → sprintf-js@1.0.3`. LokLM calls Mammoth's `convertToMarkdown` API; Mammoth imports `argparse` only from its CLI entry point, not its conversion library. The isolated DOCX test confirms this for the exercised API path. The latest reviewed Mammoth release, 1.13.0, still depends on argparse 1.x, so an in-range update would not remove the advisory. This is a reachability finding for the current document path, not a fix or a guarantee for future callers. [Mammoth package definition](https://github.com/mwilliamson/mammoth.js/blob/1.13.0/package.json).

The development copy is `electron-builder → app-builder-lib → @electron/get@3.1.0 → global-agent@3.0.0 → roarr@2.15.4 → sprintf-js@1.1.3`. All 14 reviewed global-agent logger calls use fixed message literals; remote URLs, headers and errors enter separate context objects, which roarr serializes rather than using as format strings. The proxy path is normally entered only when enabled, and roarr logging defaults off. No attacker-controlled format string was found in this reviewed chain. Global-agent 4.1.0 removes roarr, but crossing the parent's 3.x range would also change proxy/TLS behavior; that broader migration is deferred. [Upstream removal](https://github.com/gajus/global-agent/releases/tag/v4.1.0).

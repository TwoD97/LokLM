# LokLM v0.7.1

This maintenance release improves recovery, document workflows, resource
management and dependency security.

- Harden cancellation, vault locking, workspace changes and shutdown against
  late results and stale worker callbacks.
- Fix folder-sync races, document refresh checks and platform-specific
  installation paths.
- Delay indexing's GPU takeover until embedding begins, allowing parsing and
  OCR to finish first.
- Correct quantized KV-cache memory estimates and optional dynamic-K retrieval
  selection; avoid loading unused summary vectors during lexical filtering.
- Keep inline citation numbers and source-menu entries consistent. Show indexed
  text when a PDF's original file has changed.
- Improve model download retries and verified replacement while preserving
  existing files when repair fails.
- Add interrupted-upgrade recovery, stricter archive extraction and stronger
  platform/checksum validation.
- Update vulnerable dependencies and apply tested, pinned backports where an
  appropriate upstream fix is unavailable.

## Validation and limitations

Automated coverage includes application, integration, dependency-security and
native installer checks. Detailed evidence is recorded in
[the bug audit](../research/2026-10-05-bug-audit.md).

**RAG reliability remains unresolved.** The latest isolated 2B development
evaluation passed 1/3 AB cases and 0/8 AR cases under unchanged strict criteria.
Remaining failures include incorrect facts or citations, omitted explanations,
false uncertainty, request errors and formatting violations. Source links and
structured-output checks do not establish factual correctness.

**4 GB GPUs remain constrained.** The default 4B model may fit only partly on the
GPU; a measured conflict-answer check exceeded five minutes without an accepted
answer. The faster 2B diagnostic model has not replaced the production default.
No general speed or answer-quality improvement is claimed.

With the current signing configuration, **Windows artifacts are unsigned**, and
**macOS artifacts are ad-hoc signed, without Developer ID signing or
notarization**. Operating-system trust warnings may appear.

Website download links update after the release workflow verifies and publishes
the platform artifacts and their checksums. This maintenance release does not
represent a passing native RAG quality gate.

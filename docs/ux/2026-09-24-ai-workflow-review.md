# AI workflow review — 24 September 2026

This pass reviewed the renderer paths for Library/import/indexing → Chat/RAG, Translation, Writing, Quiz, and Transcription. The goal was understandable waiting and failure states, recoverable work, and honest action feedback within the existing calm workspace design. It does not change GPU residency, inference providers, retrieval defaults, or model quality.

## Practical limits / follow-up

- Writing has no cancellation endpoint; this pass deliberately does not present a button that would only hide the work. Its waiting message covers a queued model and active rewrite without implying immediate GPU execution.
- Batch transcription still processes the full queue sequentially. It does not yet offer a stop-entire-queue operation. Clear explains when it becomes available and cannot abandon visible results while work continues. A proper batch cancellation feature needs explicit worker/staging cleanup and partial-result semantics.
- These renderer tests do not prove real GPU throughput, Whisper/diarization acceleration, OCR quality, translation accuracy, or RAG answer quality. Runtime policy and native model tests are separate work. The existing transcription source comment describes an automatic CPU fallback; that runtime behavior needs its own GPU-policy review if the application must guarantee GPU-only inference across audio as well as LLM/embedding work.
- Drafts/results remain in the mounted tool view; this pass does not add durable draft recovery after closing the app or locking the vault.

## Independent auth follow-up

Read-only browser review covered Register, Login, Reset, and recovery-word reveal at 960 × 720 in light/dark themes, including pending operations, rejected requests, and clipboard failures. Only fixture passwords and public/explicitly fake recovery words were used. The review found a mouse-access blocker that axe alone did not detect: the flex layout shrank the overflowing auth card while `overflow: hidden` clipped its submit button. The outer `.app` had no scroll range. Keyboard focus or `scrollIntoView` could move the hidden card internally, disguising the problem in automated screenshots. Root fixed this by preventing the direct auth card from shrinking. A subsequent axe finding on the now-scrollable busy Register page was fixed by making `main.app` focusable.

After both production fixes, **24 auth preview states** passed with zero axe WCAG A/AA violations and no horizontal overflow: eleven English states in each theme plus German recovery-copy-error in each theme. Mouse-wheel checks reach the form actions through the outer page scroller; the auth card itself no longer clips content. Keyboard checks verified initial input focus, submitting Login with Enter, reaching Next after acknowledging recovery words, and Reset → Cancel → Login. Busy controls stayed disabled and failed copy retained every fixture recovery word. Screenshots are in `out/ux-review/auth/`; generated preview drivers are in `out/ux-research/auth-*preview.cjs`. The Settings recovery modal surface was separately checked by root.

A final independent Settings recovery-modal check found an Enter-key default action that could activate the newly focused Copy button immediately after fast regeneration. Root added `preventDefault()` to the accepted Enter handler. The browser fixture now verifies zero `copySecret` calls after generating with Enter and exactly one after an explicit Copy click. Light-modal recovery indices also failed contrast after their animation fully settled; root switched the scoped index color to the stronger existing text token. Both light/dark modal error/reveal states now pass axe, bringing this auth follow-up to **26 checked states**. The modal remains solid, Escape preserves the one-time revealed words, and Next is keyboard reachable.

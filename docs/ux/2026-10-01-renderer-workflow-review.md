# Renderer workflow and startup review — 2026-10-01

This pass addresses reproducible workflow failures and deferred rendering work. It keeps the existing visual direction. It uses the frontend-design skill and the Web Interface Guidelines for keyboard operation, focus, feedback and asynchronous state. No model-quality claims come from these checks.

## Findings and changes

| Workflow                  | Failure observed in code/tests                                                                                                        | Implemented behavior                                                                                                                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Workspace switching       | A selected store could become interactive before activation succeeded; rapid switches could complete out of order.                    | Gate store-dependent views immediately, serialize activation, skip superseded queued selections, and expose failure/Retry. Writing and translation remain available.                                                  |
| Workspace mutations       | Failed creation/rename erased drafts; the default star changed before persistence; deletion could leave the active store interactive. | Retain failed drafts, prevent duplicate submissions, change the star after saving, expose failures, and gate/reopen the active workspace around deletion.                                                             |
| Chat regeneration         | Delayed deletion/read operations could continue after navigation; retry context could include the pair being replaced.                | Capture navigation ownership, block duplicate regeneration, respect Stop before subsequent operations, reload after errors, and build retry history from the persisted prefix.                                        |
| Library search            | A rejected search looked like a successful search with no matches.                                                                    | Distinct loading, failure and empty-result states, with a Retry action.                                                                                                                                               |
| Document actions          | Destructive deletion lacked confirmation; menus did not expose keyboard menu semantics.                                               | Named confirmation, pending deletion control, Arrow/Home/End/Escape behavior and focus restoration.                                                                                                                   |
| Folder state and indexing | Old workspace reads, storage estimates or document-ID progress could replace current state.                                           | Ignore stale replies, filter progress by workspace, clear local state on workspace change, and reconcile live backfill events ahead of older reads.                                                                   |
| Bulk library operations   | Sequential retry/keep/delete loops could send old local IDs after leaving their workspace.                                            | Stop remaining operations when the originating view is unmounted. Backend workspace pinning remains a separate required protection.                                                                                   |
| Synced folders            | Disconnect removed indexed documents immediately; failures were unhandled; an empty directory selection meant “index everything.”     | Confirm disconnect, surface recoverable errors, guard pending operations and stale replies, trap picker focus, and require at least one checked folder for Save. Index everything remains explicit.                   |
| Missing-document recovery | Read/mutation failures could disappear; old results and generated-source paths could appear as missing files.                         | Visible failures, refresh after partial changes, confirmation before deletion, workspace-owned requests and exclusion of generated-source markers.                                                                    |
| Generated documents       | A document with no original disk file offered original-file actions, and pending indexing prevented reading durable content.          | Retain Read/Export/Reindex/Replace; omit Reveal/Open original/Refresh. Read encrypted generated text before indexing completes and render Markdown by MIME. Backend source storage/export are implemented separately. |
| Organizer typing          | Date formatters and saved-note previews were repeatedly rebuilt during unrelated edits.                                               | Memoize formatters per locale, selected calendar entries, and saved-note excerpts. No date/storage semantics changed.                                                                                                 |
| Reader accessibility      | Keyboard focus could leave a document modal.                                                                                          | Trap and restore focus in readers, including the lazy-loading placeholder; Close and Escape work while imports are pending.                                                                                           |

Chat input and conversation navigation are memoized so assistant token updates do not repeatedly render unchanged controls.

## Remaining limits

- Regeneration now requests one atomic deletion of the exact latest adjacent user/assistant pair. Workspace, conversation, IDs, and roles are checked before both deletes inside the SQLite transaction; visible history must also match the fresh stored history. The renderer retains the question in the composer if Stop arrives during the admitted deletion and does not send after navigation. The 12 renderer/input checks and five real encrypted SQLite checks pass, including a SQLite trigger that aborts the second delete and verifies both messages and cascading citations after reopening the encrypted file. Deletion and the later model generation remain separate operations: an admitted regeneration can remove the old exchange before a later inference failure.
- Adding a codebase folder currently persists its connection before directory selection. The add flow still requires an indexing choice; this change does not introduce a Cancel action that silently leaves an unrestricted connected folder for a later automatic sync.
- Stopping navigation-owned bulk work stops subsequent calls; an already accepted backend operation finishes under its backend lifetime rules.
- Generated-file export, encrypted source durability, backend workspace isolation and native indexing are validated separately from this renderer review.

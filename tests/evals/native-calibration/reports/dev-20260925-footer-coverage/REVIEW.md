## Recommendation: keep source-marker footers opt-in

The four-case control/on pair is promising: DEV-06 changes from correct arithmetic with wrong planned-value attribution to the correct two table citations; the other three answers remain supported. All recorded source/build/model hashes and source text match, and those four pairs receive identical passage sets/order. However, the first query's runtime KV differs (control q8_0, on f16), so the observed improvement is not clean isolated causal proof. There is only one observation per case per arm.

Broader checks do not justify enabling the footer by default yet. The separate conflict regression preserves all four authority decisions, but the German unresolved answer still omits both dates and the German approved answer adds a historical date without its exact source citation, while ignoring the ISO format request. DEV-12 demonstrates that even a real, allowed passage ID can accompany an unsupported paraphrase. Footers repeat source identity; they do not verify claim entailment.

Keep `LOKLM_SOURCE_MARKER_FOOTERS=1` available for explicit further evaluation and leave the default off. The accepted GPU-resource and chat persistence/citation-membership fixes are independent of this decision. No silent citation rewrite or claim of verified factuality is warranted. Any later default reconsideration should use a new predeclared comparison with matched resolved allocation and independent exact-clause review, rather than tuning on these diagnostic answers or treating this corpus as a general accuracy estimate.

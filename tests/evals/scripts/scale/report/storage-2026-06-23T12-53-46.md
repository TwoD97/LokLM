## Cold workspace open (decrypt-on-open of the full encrypted store)

At 5.0M vectors: decrypting 22.25 GB took **2.3 min** (163 MB/s). This is paid on EVERY unlock/switch into the workspace, and while open the plaintext `work/` copy doubles the on-disk footprint.

## Extrapolation to 100 GB of text

- avg chunk size (measured): 508 B → **196.8M chunks/vectors**
- LanceDB on disk: 4448 B/vec → **875.17 GB** at rest
- while OPEN: enc/ + plaintext work/ coexist → **1750.34 GB** of disk needed
- one-time embed (GPU, upper bound): **37.1 d**
- decrypt-on-open at that size: **1.5 h** PER unlock
- query latency: IVF-PQ at 5M held query p95 at 43 ms; ANN search is sub-linear, so query latency is NOT the wall.

## Out of scope (flagged follow-up)

- Encrypted SQLite (meta.db) + FTS5/BM25 scaling: `better-sqlite3-multiple-ciphers` is built for Electron's ABI (NODE_MODULE_VERSION 146), not node (137), so it can't run in this headless harness. Needs an in-Electron run or a node-ABI rebuild (which would break the app build).
